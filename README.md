# Telegram-бот для оформления заказов СДЭК

Переносит создание заказа из личного кабинета СДЭК для бизнеса в Telegram (API СДЭК v2, aiogram 3).

## Возможности

**Оформление заказа** — пошаговый мастер:

1. Тип заказа: интернет-магазин (с товарами, номером заказа ИМ и наложенным платежом) или «Доставка».
2. Город отправления и город получения ищутся по началу названия.
3. Грузовые места: `1.5 30x20x10`, можно указать несколько строк, количество и описание вложения.
   Для ИМ бот спрашивает товары каждого места: `Название + цена + вес + кол-во + артикул`.
4. Тариф. Бот показывает список из калькулятора СДЭК с ценой, сроком и режимом
   (🚪 дверь / 🏢 ПВЗ / 📮 постамат). Код тарифа можно ввести и вручную.
5. ПВЗ или постамат отправки и получения. Пункт можно найти тремя способами: выбрать из списка, написать часть адреса, метро или код, либо прислать геолокацию, и бот покажет ближайшие пункты. Если тариф «от двери» или «до двери», бот спрашивает адрес.
6. Страховка: объявленная стоимость (для ИМ считается по стоимости товаров).
7. **Оплата получателем** (для ИМ): ничего, только товары (наложка), товары + доставка или только доставка.
   Сумму за доставку можно задать фиксированно (`390`) или **наценкой в % к тарифу СДЭК** (`15%` или кнопки +10/20/30%).
   Наценка пересчитывается от актуального тарифа при создании заказа и округляется вверх до рубля.
   В сводке видно, сколько взять с получателя и какая маржа на доставке. Наценку можно сохранить в шаблон.
8. Доп. услуги (примерка, частичная доставка, осмотр вложения, доставка в выходной, реверс, опасный груз, SMS и др.)
   и упаковка (коробки XS–L и 500 г–30 кг, сейф-пакеты, плёнка, наполнитель), у упаковки задаётся количество.
9. Отправитель и получатель вводятся одним сообщением или контактом из Telegram.
10. Комментарий.

В конце бот показывает **сводку с расчётом стоимости** (доставка, каждая услуга и итог, срок). Любой блок можно изменить кнопкой ✏️. На любом шаге работает «↩️ Назад».

**Шаблоны с частичным сохранением.** Кнопка «💾 В шаблон» в сводке (или команда `/savetpl` на любом шаге)
показывает список заполненных полей. Можно отметить любой набор, например *город + ПВЗ отправки + тариф*.
При создании заказа из такого шаблона бот задаёт вопросы **только по незаполненным полям**.
Если пункт из шаблона несовместим с выбранным тарифом или городом, бот автоматически сбросит его и спросит заново.

**После создания заказа:** статус, накладная и штрихкод в PDF, вызов курьера (для тарифов «от двери»),
повтор заказа и удаление. Есть отслеживание по номеру СДЭК и история последних заказов.

## Запуск

```bash
python3 -m venv .venv && . .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env   # заполнить BOT_TOKEN, ключи СДЭК, ALLOWED_USERS
python -m bot
```

- `CDEK_TEST=1` — тестовый контур `api.edu.cdek.ru`. Если ключи не заданы, используются публичные тестовые ключи.
  Для боевой работы: `CDEK_TEST=0` и ключи из ЛК (Интеграция → Ключи API).
- `ALLOWED_USERS` — список Telegram ID через запятую. **Обязательно заполните**, иначе ботом сможет пользоваться любой
  и создавать заказы по вашему договору. Бот сообщит свой ID пользователю, которому отказал в доступе.
- `SHARED_TEMPLATES=1` — общие шаблоны для всей команды.
- `REDIS_URL` — хранить состояние диалогов в Redis (иначе в памяти, и при перезапуске незаконченные черновики теряются).

## Развёртывание на сервере

Бот работает в режиме long polling: он сам ходит в Telegram, поэтому ему **не нужны** домен, HTTPS и открытые
порты. Нужен сервер, где можно держать постоянно запущенный процесс (VPS или VDS). Обычный виртуальный хостинг
сайта (PHP + FTP) не подойдёт. Бот можно запустить на том же VPS, где работает сайт, с ним он никак не пересекается.

**Вариант 1. Docker** (проще всего):

```bash
git clone <URL репозитория> /opt/cdek-bot && cd /opt/cdek-bot
cp .env.example .env && nano .env      # BOT_TOKEN, ключи СДЭК, CDEK_TEST=0, ALLOWED_USERS
docker compose up -d --build
docker compose logs -f                 # логи
```

**Вариант 2. systemd** (нужен Python 3.11+):

```bash
sudo useradd -r -m -d /opt/cdek-bot cdekbot
sudo -u cdekbot git clone <URL репозитория> /opt/cdek-bot
cd /opt/cdek-bot
sudo -u cdekbot python3 -m venv .venv
sudo -u cdekbot .venv/bin/pip install -r requirements.txt
sudo -u cdekbot cp .env.example .env && sudo -u cdekbot nano .env
sudo cp deploy/cdek-bot.service /etc/systemd/system/
sudo systemctl daemon-reload && sudo systemctl enable --now cdek-bot
```

### Если Telegram недоступен с сервера

Признаки: бот не отвечает, а `curl https://api.telegram.org` с сервера зависает.

**Через Cloudflare Worker** (бесплатно):
1. Откройте dash.cloudflare.com → **Workers & Pages** → **Create** → **Create Worker**, задайте имя (например `tg-proxy`) → **Deploy**.
2. **Edit code**: вставьте содержимое `deploy/cloudflare-worker.js` и в `ALLOWED_BOT_ID` впишите ID бота (число до `:` в токене). → **Deploy**.
3. В `.env` бота: `TELEGRAM_API_URL=https://tg-proxy.<ваш-аккаунт>.workers.dev`, затем `docker compose up -d`.

Проверка с сервера (должно вернуть `"ok":true`):
`curl https://tg-proxy.<ваш-аккаунт>.workers.dev/bot<ТОКЕН>/getMe`

**Через прокси**: `TELEGRAM_PROXY=socks5://user:pass@host:1080` (или `http://...`).

Обновление: `git pull`, затем `docker compose up -d --build` или `sudo systemctl restart cdek-bot`.
Шаблоны и история хранятся в SQLite (`data/` или `DB_PATH`), их стоит включить в бэкап.

## Тесты

```bash
pip install pytest pytest-asyncio
python -m pytest -q
```

`tests/test_e2e.py` прогоняет настоящий диспетчер и хэндлеры с фейковым Telegram и моком API СДЭК.
Там проверены полный заказ, частичный шаблон, заказ из шаблона, ИМ с товарами и наложкой, печать, редактирование и «назад».

## Устройство

```
bot/
  __main__.py     запуск, доступ по ID, обработка ошибок
  cdek.py         клиент API v2 (OAuth, города, ПВЗ, калькулятор, заказы, печать, курьер)
  catalog.py      справочники: режимы, тарифы, доп. услуги/упаковка, блоки шаблонов
  draft.py        модель черновика: порядок шагов, разбор ввода, сводка, сборка запросов к API
  wizard.py       движок мастера: спрашивает следующий незаполненный шаг
  handlers/       order (шаги), templates, orders (после создания), common (меню)
```

Черновик заказа устроен как словарь: если ключ есть, шаг считается заполненным. Шаблон хранит подмножество этих ключей, поэтому
частичные шаблоны не требуют отдельной логики: мастер просто идёт по `STEPS` и спрашивает недостающее.

Чтобы добавить услугу или тариф, допишите их в `bot/catalog.py`. Доступность услуг зависит от вашего договора:
если СДЭК отклонит услугу, бот покажет текст ошибки.

## Ограничения

- Международные отправления (паспортные данные, таможенные поля товаров) не реализованы.
- Оплата доставки получателем есть только у заказов «Интернет-магазин» (`delivery_recipient_cost`). У «Доставки»
  плательщик определяется договором, в API v2 для отдельного заказа его не задать.
- НДС по товарам не передаётся (считается «без НДС»).
- Список кодов доп. услуг взят из документации API v2. Сверьте его с вашим договором в тестовом контуре.
